Початковий checkout: `a0f15042`. План складено до змін коду. Використано готовий паралельний аудит `docs/ui-plan-zavtra.md` із сусіднього checkout; його дослідження ролей, станів та scanner тут не повторюється.

## Підтверджені місця і порядок роботи

1. **Поле повідомлення.** `src/components/ComposerBar.tsx:471` починається з одного рядка; desktop на рядках 554–565 ділить ширину тексту з мікрофоном і надсиланням. `src/hooks/useAutosizePinned.ts:36` перемірює лише зміну тексту/лімітів, тому звуження панелі переносить рядки без збільшення висоти. Зробити поле повної ширини, дворядковий початок із дотриманням мобільного бюджету, вимірювання ширини. Зберегти звичайну багаторядкову вставку, IME-захист, чергу та Shift+Enter; перевірити Enter на мобільній клавіатурі й повернення фокусу.
2. **Часті дії поруч із текстом.** Надсилання, вкладення і диктування — один рядок під полем, щоб не звужувати текст. Режим/runtime — у тому ж рядку з переносом при нестачі місця. Рідкісні альтернативи надсилання зараз доступні лише контекстним меню (`ComposerBar.tsx:312`): дати видиму кнопку меню. Налаштування згрупувати під підписами: робота, доступ та інфраструктура, поведінка застосунку (`src/components/mobile/MobileRootScreen.tsx:65`). HQ і проєкти зберігають основні входи; глобальну навігацію не перебудовувати.
3. **Згадки.** `src/components/mobile/MobileHqRoom.tsx:140` і `src/components/orchestrator/OrchestratorConversation.tsx:53` передають звичайний composer без каталогу адресатів. Додати пошук після `@`, клавіатуру та вибір із живих розмов. Вставляти читабельне посилання зі стабільним conversation ID: дублікати назв не визначають адресата, перейменування не змінює його. Згадка є контекстом повідомлення HQ, а не автоматичним дорученням іншому агенту.
4. **Видимі дії HQ.** `src/components/runtime/McpCallCard.tsx:157` вже має details, але вміст — технічний JSON, заголовок обрізано; успішний виклик інструмента на рядку 145 не доводить доставку. Для повідомлень/створення агентів показати адресата, повний текст у розкритті, посилання на розмову та точний відомий статус. Технічні аргументи — другим розкриттям. Не вгадувати повідомлення з довільного shell-коду.
5. **Чесний редактор ролей.** Аудит уточнив: `src/lib/roles/store.ts:88` кидає помилку на невідомий ID, а не мовчки відкидає. Каталог із console показує додаткові ролі, POST `src/app/api/roles/route.ts:131` їх відхиляє. У межах UI показати підтримуваність дій, Refresh/Retry і помилку над старими даними. `src/components/mobile/MobileRolesScreen.tsx:82` не оновлює draft після Reset у відкритому рядку; рядок 127 пропонує Reset без відомого seed. Виправити ці конкретні кнопки й перенос довгих полів/дій. Наскрізну міграцію ролей, політик дозволів і pipeline залишити окремій роботі з аудиту.

## Перевірка та межі

Лише адресні DOM/unit-тести в приватному state-каталозі, TypeScript без emit і lint змінених файлів. Якщо середовище не виконає Bun-тести, використати окремий тимчасовий checkout на машині публікації. Перед пушем — privacy gate і перегляд diff. Коміти невеликими кроками українською, PR через машину з належною авторизацією; без перенесення токенів.

Не змінювати живий checkout, не білдити, не запускати/рестартити дошку, не мержити main, не запускати агентів. Без нових UI-бібліотек, градієнтів, важких тіней, міграцій даних і змін runtime-host. Візуальну перевірку живої версії не видавати за перевірку цієї гілки.

### Чому функції розташовані саме так

- **Чат і сесії** залишилися прямими щоденними входами. **Settings** — третій нижній вхід. MCP і Secrets перенесені з нижньої навігації в Settings: видавання доступу й підключення сервера належать до налаштування роботи, а не до кожного повідомлення. На телефоні замість п'яти тісних пунктів три підписані кнопки.
- **Робота й історія:** фірми, ролі, архів. Це налаштування складу роботи та повернення до завершеного. Вони згруповані перед інфраструктурою.
- **Доступ і підключення:** акаунти, секрети, дозволи, MCP, канали, машини. Тут оператор вирішує, хто і через що працює. Автобаланс акаунтів стоїть поруч із цими налаштуваннями, а не серед звукових перемикачів. Інформація про хост лишається в цій групі.
- **Поведінка застосунку:** звук і утримання екрана. Ці особисті перемикачі мають спільний розділ. Desktop-меню повторює групи роботи та доступу.
- **Composer:** текст займає повну ширину; модель, вкладення, голос і Send стоять під ним із переносом при нестачі ширини. Рідкісні способи надсилання відкриваються окремим меню. На мобільному Enter додає рядок, кнопка або Ctrl/Cmd+Enter надсилає; на desktop Enter надсилає, Shift+Enter додає рядок. IME-підтвердження не надсилає.

### Згадки та дії агентів

Список після `@` містить живі розмови зі стабільним ID, без поточного HQ і дублів. Назва, проєкт, роль та короткий ID допомагають відрізнити однаково названих агентів. У чернетці лишається коротке ім'я, його відповідність ID зберігається разом із життєвим циклом чернетки. У чергу потрапляє звичайне Markdown-посилання `[@ім'я](#c=conversation_example)`. Вибір не надсилає доручення сам по собі; адресатом повідомлення залишається HQ.

Записані Viewer-виклики `send_message`, `send_message_to_orchestrator`, `spawn_agent` отримали читабельний акордеон: адресат, текст, посилання на розмову, зафіксований статус. Прийнято до доставки не означає доставлено. Технічний JSON розкривається окремо. UI не повторює виклик і не запускає polling. Попередній перегляд тексту збільшено до 20 тисяч символів із явним повідомленням про скорочення; загальне обмеження запису й приховування секретів збережено.

### Перевірки та залишені межі

- **133 успішні адресні тести у 20 файлах**, окремими процесами з приватним state і відсутнім реальним console. Перевірені вкладення, допуск до надсилання, IME/фокус, черга, voice-owner, згадки, розбір дій, клавіатура/висота, навігація та API ролей. Тест API ролей більше не залежить від установленого на машині fleetctl.
- **Playwright/Chromium:** 320, 390, 430 та 1280 px. Реальні компоненти, кліки й введення; остання роль/правило досяжні прокруткою, Reset/Save застосовують прочитаний результат, readonly не пропонує Save, помилка Refresh видима над старими даними, вибір другого однаково названого агента зберігає його ID, меню і Send залишаються у viewport. Мобільну клавіатуру перевірено через зміну `visualViewport`; фізичний Safari/iOS не перевірявся.
- Відтворення: `bun scripts/verify-ui-consolidation.cjs`; інші ширини задає `UI_TEST_WIDTH`. Скрипт компілює лише браузерну тестову сторінку в тимчасову теку, перехоплює API й не запускає Viewer/runtime-host. Потрібен Chromium; шлях можна задати `CHROMIUM_PATH`. Скриншоти містять виключно синтетичні дані.
- **TypeScript:** `tsc --noEmit --incremental false` пройшов на машині публікації; локально стандартного ліміту пам'яті Node не вистачило. Залежності репозиторію не змінювалися.
- **Lint:** штатний ESLint 10 падає всередині `react/display-name` через несумісний `context.getFilename`. Додатковий запуск ESLint 9 на змінених файлах дає ті самі 17 діагностик, що й checkout `a0f15042` (10 помилок, 7 попереджень); нових немає. Це не твердження про зелений lint усього репозиторію.
- Повна підтримка нових рольових ID у запуску, store, presets і pipeline залишається окремою міграцією з паралельного аудиту. Тут усунено неправдиву редагованість і зламані Reset/Refresh; додаткові ролі видно, але вони явно лише для читання.
- Збірка/рестарт Next, зміни живого checkout, runtime-host, merge і deploy не виконувалися. Результат — ця гілка та PR.
