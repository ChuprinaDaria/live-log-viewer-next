# Десктоп: чат з HQ + пульт проєкту замість дошки

Дата: 2026-09-08. Замовниця: Даша. Автор: Дітріх.

## Навіщо

Десктоп сьогодні відкривається на дошку: рейл проєктів зі слагів тек
транскриптів, картки-«ноди» і звʼязки агентів. Замовниця сказала прямо:
«замість канвас і звʼязки агентів мені потрібен чат з оркестратором і вибір
проєкта, скілів, сікретів, агентів». Телефон уже так і працює (вкладка «Чат»
= HQ-кімната, `MobileHqRoom`); десктоп має отримати ту саму структуру, тільки
поруч, а не вкладками.

## Що змінюється

### Головний екран десктопа (≥ 640 px)

```
┌────────────┬──────────────────────────────────┐
│ Пульт      │  Чат з HQ (той самий компонент,  │
│ (280 px)   │  що на телефоні, без мобільного  │
│            │  хрому)                          │
│ фірма →    │                                  │
│  проєкт    │                                  │
│  проєкт    │                                  │
│ фірма →    │                                  │
│  …         │                                  │
│ Без проєкту│                                  │
│ ─────────  │                                  │
│ [Створити  │                                  │
│  агента]   │                                  │
│ обраний    │                                  │
│ проєкт:    │                                  │
│  агенти    │                                  │
│  скіли     │                                  │
│  секрети   │                                  │
│  MCP       │                                  │
└────────────┴──────────────────────────────────┘
```

- **Дерево** читається з пульта (`useOrg`: `/api/firms`, `/api/projects`,
  `projectTree`), не з тек транскриптів. Підпапки з відступом. Сесії, чий
  `file.org` відсутній, рахуються в один згорнутий рядок «Без проєкту» внизу;
  розкриття показує їх старим списком проєктів (`buildProjectSummaries`).
  Далі їх перебере агент-сортувальник — це не наша робота.
- **Чат** — `MobileHqRoom` під `SuppressMobileTabs`, як це вже робить
  `DesktopMenu` для інших мобільних сторінок. Один seat `fleet-hq`. Стан
  «порожньо / запускається / кімната» — той самий.
- **Дошка** (старий `OverviewBoard` + `ProjectDashboard` + `ProjectRail`)
  нікуди не зникає: кнопка «Дошка» у шапці перемикає центр на неї, і назад
  «HQ». Вибір зберігається в `localStorage`, дефолт — HQ.

### Блок обраного проєкту

Клік по проєкту в дереві:

1. Під деревом зʼявляється блок з `project_show` (`loadProject`):
   - **Агенти** — сесії, у яких `file.org.project === id`, рядок:
     назва, рушій+модель чипом, акаунт дрібним, машина (`walter` для локальних
     транскриптів; інше — лише коли транскрипт про це каже, інакше нічого не
     вигадуємо). Тап → відкриває розмову в центрі (існуючий `openFile`
     через `ProjectDashboard`, кнопка «HQ» повертає в чат).
   - **Скіли / MCP** — `effective.skills`, `effective.mcp` з підписом
     «власні» або «від фірми X». Перемикач: власні можна зняти
     (`/api/mcp-registry` revoke), з реєстру можна видати проєкту.
   - **Секрети** — `effective.secrets` з підписом джерела; зняти/видати через
     `/api/secrets` share/unshare. Значень немає ніде.
2. Кнопка **«Сказати HQ»** — шле в кімнату один рядок
   «Відкриваю проєкт <фірма> → <проєкт> (<шлях>)». Без магії: HQ-мандат уже
   описує, що робити, коли оператор називає проєкт.
3. **«Створити агента»** — відкриває існуючу форму машин
   (`MobileMachinesScreen`) у правій панелі з уже обраним проєктом. Список
   проєктів у формі групується по фірмі (`<optgroup>`), а не плоско.

### Телефон

Не змінюється, окрім: кнопка «Створити агента» зверху вкладки «Сесії»
(відкриває той самий екран машин), і групування проєктів по фірмі у формі.

## Чого не робимо

- Не переносимо канвас на телефон і не видаляємо його з коду.
- Не робимо ssh-доставку повідомлень у сесію на іншій машині: запуск і
  перенесення працюють, спілкування з віддаленою сесією з дашборда — окремий
  етап, після цього.
- Не автосортуємо сесії по проєктах. «Без проєкту» — чесне відро.
- Не міняємо стек, не міняємо мобільну навігацію.

## Етапи (кожен окремо комітиться і викочується)

1. **Каркас.** Десктоп відкривається на «пульт + HQ». Дерево з пульта,
   «Без проєкту», перемикач «Дошка / HQ». Тести: dom-тест, що при
   `useIsMobile() === false` рендериться дерево і HQ, а дошка — після кліку.
2. **Блок проєкту + створити агента.** Агенти, скіли, секрети, MCP з
   джерелом, перемикачі, «Сказати HQ», кнопка створення з передзаповненим
   проєктом, optgroup по фірмі. Тести на модель блоку (чиста функція:
   `effective` → рядки з підписом джерела) і на кнопку.
3. **Розмова агента з пульта.** Тап по агенту → його розмова в центрі,
   «HQ» назад; «перенести» і «змінити акаунт» у меню розмови на десктопі
   (той самий код, що на телефоні).

## Критерії приймання

- Відкривши десктоп, Даша бачить чат з HQ і список фірм, а не картки.
- Один клік — проєкт, і видно, які скіли, секрети, MCP на ньому діють і які
  агенти в ньому живуть.
- «Створити агента» — не глибше одного кліку, проєкт уже підставлений,
  машина обирається зі списку.
- Жодних вигаданих даних: порожній блок каже «нічого не діє», а не малює.
- Мобільний набір тестів не отримує нових падінь (перевірка тими самими
  файлами, не всім набором).
